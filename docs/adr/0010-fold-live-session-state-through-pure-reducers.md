# Fold live session state through pure reducers with delta-owned fields

The session page used to keep messages, parts, prompts and status in several pieces of state, each patched by its own SSE handler, with temporary message IDs, module-level caches and length-based heuristics to decide whether a snapshot or a streamed delta was newer. Every one of those was an invalidation surface, and the visible failures were tool blocks that appeared only after a refresh, streamed text that rewound or blanked, optimistic user messages that vanished, and reconnects that left gaps.

The page now owns one `SessionView`. Pure reducers fold every input into it: `frontend/src/lib/sessionReducer.ts` handles REST loads and client actions, and `frontend/src/lib/conversation/conversationReducer.ts` handles conversation stream batches. Both are tested without React and return the same state reference for no-op actions. A load merges server messages and parts over in-memory ones by ID instead of replacing the view, because OpenCode's database write can lag its stream and a wholesale replace would briefly erase live content.

Append-only streaming fields use longest-wins reconciliation, not unconditional local ownership. For each delta-owned `(partId, field)` pair, a REST snapshot keeps the longer of its incoming value and the locally accumulated value. Non-final conversation upserts likewise keep the longer streamed value. This prevents a lagging snapshot from shortening live text while allowing a newer snapshot to fill in content missed during a session revisit or reconnect. Other fields take the snapshot value. Final conversation upserts are authoritative replacements, including corrections that shorten streamed content. These merge rules live in `frontend/src/lib/sessionViewParts.ts` and `frontend/src/lib/conversation/conversationParts.ts`. Optimistic sends live outside the view in `usePendingSend`, so the view never holds temporary IDs that later need reconciling.

Consequences: streamed text does not shrink during non-final reconciliation, and reconnects heal through a merge rather than a reset. A longer snapshot can advance a delta-owned field beyond cached content; a final conversation upsert can replace it outright. Longest-wins relies on the append-only streaming contract and is not a general conflict-resolution rule for arbitrary edits. New live behavior is added as a reducer case with a direct test, not as another handler with its own state.
