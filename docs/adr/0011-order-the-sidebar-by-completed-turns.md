# Order the session sidebar by attention events

With several agents running at once, ordering sidebar rows by the session's last update made them jump while they streamed: every token, tool step or title change moved a row to the top, so the list never settled while the user was trying to pick a session. We looked at how other clients handle this. Open WebUI sorts by a broad `updated_at` and keeps unread state separate, Slack separates ordering from its unread workflow, and Codex distinguishes completion from required input in notifications without documenting its sidebar order. Ocman's concurrent-agent workflow calls for ordering by discrete attention events rather than continuous activity.

Ordinary rows sort newest first by `max(lastUserPromptAt, lastHaltAt, lastTurnCompletedAt)`, falling back to creation time when all three are absent or zero. Pinned sessions keep their pin order. A user prompt, halt or completed top-level assistant turn advances the key; errors count as completed turns, but tool steps and compaction summaries do not. Streaming output, title changes, viewing a session and marking it read do not advance it. The canonical message projection is `internal/statev2/sidebar_attention.go`, supplemented by halt metadata; `frontend/src/lib/sidebarHelpers.ts` combines the three timestamps with a stable platform/session-ID tie-breaker. These are durable event times, not browser receipt times, so polling, reconnect replay and restarts do not make an old event look new.

Unread and needs-input state stay independent of order. A completed, unseen reply marks the row unread, and reading clears that without moving it. Permission and question prompts show their indicators as soon as they are asked, before the turn completes.

Consequences: resuming an older conversation brings it above inactive ones immediately on the user prompt, and a halt or completed turn brings it back to attention. Streaming alone does not continually reorder the list. A long-running session can sink below others with newer attention events; its status indicator, not its position, signals ongoing activity.
