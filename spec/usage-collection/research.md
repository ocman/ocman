## Findings from implementation

### Endpoint, vendor, and delivery

- The server sends JSON batches to **`https://ingest.t3.codes/batch/`**, not directly to a PostHog cloud hostname. `T3CODE_POSTHOG_HOST` and `T3CODE_POSTHOG_KEY` override the bundled host/project key. The body has `api_key` and a batch of events. Each event carries a UUID, event name, `distinct_id`, properties, and capture timestamp. `$process_person_profile: false` disables PostHog person-profile processing, not identifier collection. [Configuration](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/server/src/telemetry/AnalyticsService.ts#L67-L80), [payload and HTTP request](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/server/src/telemetry/AnalyticsService.ts#L199-L235).
- Default buffering is 20 events per batch, at most 1,000 queued events, with a 10-second background flush. Failed batches back off and can retry for 30 minutes; shutdown gets one second. This is best-effort event delivery, not a local weekly aggregate. [Limits](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/server/src/telemetry/AnalyticsService.ts#L42-L80), [retry/drop](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/server/src/telemetry/AnalyticsService.ts#L264-L300), [flush](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/server/src/telemetry/AnalyticsService.ts#L353-L359).
- **First-party documentation, not independently verified ingest behavior:** T3 says ingest archives every event and forwards some to PostHog. The reviewed public client code establishes the outgoing request, not backend storage, forwarding rules, PostHog region, or retention. [Internal delivery documentation](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/docs/internals/product-analytics.md#L135-L150).

### Identity and persistence

- `distinct_id` is SHA-256 of Codex `tokens.account_id`, else Claude `.claude.json` `userID`, else a generated installation UUID. Codex input comes from `~/.codex/auth.json`. Its account ID can represent a shared workspace, not one person. A separate `installId` is the hash of the persistent random UUID in `<stateDir>/anonymous-id`. Existing UUIDs are reused; no expiry/rotation appears in this path. [Identity selection and file reads](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/server/src/telemetry/Identify.ts#L219-L295), [filename](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/server/src/config.ts#L170-L172).
- Owner observations additionally hash linked T3 Connect account, OpenAI person `user_id` decoded from the ID token, and Claude `oauthAccount.accountUuid`. These link installations beyond the legacy distinct ID. Tokens are read locally to extract identifiers, not sent by this payload builder. [Owner extraction](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/server/src/telemetry/Identify.ts#L302-L339).
- Web clients persist a random UUID in localStorage under `t3code:analytics-device-id`; mobile analytics reuses a UUID saved through mobile secure storage. Client Connect/device identifiers are hashed before being put in connection URL parameters. [Web persistence](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/web/src/connection/platform.ts#L312-L325), [mobile use](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/mobile/src/connection/platform.ts#L196-L204), [mobile persistence](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/mobile/src/persistence/mobile-storage.ts#L128-L137), [client transmission](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/packages/client-runtime/src/authorization/remote.ts#L55-L62), [URL parameters](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/packages/client-runtime/src/authorization/remote.ts#L108-L113).
- Hashing is plain SHA-256, with no salt or secret. Equal raw identifiers produce equal hashes across clients and servers. This is **persistent pseudonymous collection**, not identifier-free aggregation. [Hash implementation](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/packages/shared/src/telemetryId.ts#L1-L12).

### Default and controls

Product collection defaults **on**. `T3CODE_TELEMETRY_ENABLED=false` disables recording and sending; managed policy can force it off, never on over an environment opt-out. Desktop startup temporarily suppresses events while current-shell preference discovery is pending, but the discovered preference still defaults to true. Identity initialization occurs even when sending is disabled. [Default and policy/preference gate](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/server/src/telemetry/AnalyticsService.ts#L67-L80), [initialization](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/server/src/telemetry/AnalyticsService.ts#L121-L148), [record gate](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/server/src/telemetry/AnalyticsService.ts#L312-L320).

The user guide instructs setting the variable before startup and restarting. Desktop reads shell profiles on macOS/Linux and user environment on Windows. **Separate channels are not a global opt-out:** the guide says browser/mobile relay traces can continue despite server opt-out; mobile crash-report settings do not control relay tracing; agent-activity publishing is separately controlled and can send titles. Axiom is the documented diagnostics vendor. These are documentation findings, not an exhaustive diagnostic-payload audit. [Controls and diagnostics boundaries](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/docs/user/telemetry.md#L15-L61).

## Exclusions, privacy risks, and policy distinction

- The explicit product payload builders above select metadata and measurements rather than forwarding prompts, responses, files, raw provider events, authentication tokens, conversation IDs, or child output. The user guide states those exclusions. Model labels are catalog-filtered and provider instance IDs are replaced with driver kinds, avoiding user-assigned names. This supports a bounded product-event claim, **not** a promise that all network traffic or diagnostic errors exclude sensitive text. [Stated exclusions](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/docs/user/telemetry.md#L3-L20), [model/provider filtering](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/server/src/telemetry/ProviderDimensions.ts#L8-L85).
- Stable installation, provider-account and device hashes permit longitudinal and cross-installation correlation. Exact event times, machine/client dimensions, token volumes and project/thread counts add behavioral detail. Disabling person profiles does not remove those links. Client owner hashes also occur in URLs, so URL logging deserves attention. These are privacy-risk inferences from the cited payload and identity code, not evidence of misuse.
- **IP:** no explicit IP field or `$ip` suppression is visible in the inspected batch builder. HTTPS does not hide the sender's egress IP from the receiving network/edge. Product ingest sees the server's egress address, not necessarily the end user's browser address. Whether ingest/CDN logs retain IPs, geolocate them, attach them to archived events, or forward them to PostHog is **unknown** from this audit. Do not equate an absent JSON IP field with absence of IP processing.
- The repository's privacy policy, effective/updated **2026-10-06**, calls default product usage data "anonymous." It separately permits automatic IP/device/browser/request/diagnostic logging. That wording is a policy statement; the implementation demonstrably sends stable, linkable hashes. [Dates](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/marketing/src/pages/privacy-policy.astro#L19-L25), [usage/IP language](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/marketing/src/pages/privacy-policy.astro#L84-L107).
- Policy says no AI training with personal information/code/prompts/responses and no sale or targeted-advertising sharing. It says operational traces expire after 30 days, with exceptions. These are **policy commitments, not source-proven backend behavior**, and 30 days must not be presented as product-event retention. Product archive/PostHog retention remains **unverified**. [Training](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/marketing/src/pages/privacy-policy.astro#L171-L175), [sale/ads](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/marketing/src/pages/privacy-policy.astro#L318-L322), [retention](https://github.com/pingdotgg/t3code/blob/31eea883c7f7849ada6eb49265cb11fc64d2ecbd/apps/marketing/src/pages/privacy-policy.astro#L361-L376).

## Recommendation for ocman, not a T3 finding

Based on parent-session context, not additional ocman investigation: existing diagnostic OTLP is optional/user-configured, and foreground active time is already credited locally and exported without client/user/date metric attributes. Keep a proposed product-usage channel separate from that diagnostic OTLP configuration and consent.

Prefer explicit **opt-in**, local weekly coarse aggregates, a preview of the exact report, and a clear off/delete-pending control. Send broad active-time/count buckets and only necessary coarse version/platform dimensions. Do not send raw intervals, event timestamps, project/thread metadata, provider-account hashes, device/install IDs, or other stable IDs. Avoid retries that require persistent identity. Keep receiver access logs disabled or IP-redacted with short documented retention; do not forward IP headers or enable vendor identity/geolocation enrichment. Publish retention and deletion limits for both aggregate storage and operational logs.

This design measures voluntary reports and approximate activity, **not exact unique users**. Multiple installations, repeat submissions, offline clients and non-consenting users prevent that inference. Do not introduce stable identifiers or IP-based deduplication merely to label a chart "users."
